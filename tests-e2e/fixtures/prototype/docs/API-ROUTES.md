# Express REST API Route Map — reverse-engineered from client-side handlers

**194 distinct `window.*` handlers** were extracted directly from the tested codebase.
Each currently mutates an in-memory array and re-renders the UI; migrating to a real backend means
each becomes a REST endpoint that mutates a MongoDB document and returns the updated resource. The
HTTP verb below is inferred from the handler's own naming convention (add/create → POST,
update/approve/toggle → PATCH, remove/delete → DELETE), which the codebase already follows
consistently — a good sign for a clean migration.

All routes should sit behind the same role-gating already enforced client-side via `canWrite()`
and `WRITE_ROLES` (Administrator, Principal, Teacher) — this must be re-enforced server-side,
never trusted from the client alone. See SECURITY-COMPLIANCE.md.

**Caveat, stated plainly:** this list was generated by parsing all 194 handlers automatically —
most genuinely mutate a collection and map directly to a real endpoint, but a small number (e.g.
`crmCopyDraft`, which only copies text to the clipboard) are pure client-side UI helpers with no
server-side equivalent needed. Treat this table as a strong first draft to prune during Phase 1 of
`MIGRATION-ROADMAP.md`, not a final, unreviewed contract.
