# Hostel

The released boarding workspace loads all saved rooms, gate passes, date-based roll-call and staff maintenance records with search, pagination, CSV exports and responsive details. Administrator, Principal and Teacher manage boarding. Parent/Student sees only linked boarders, their room allocation, gate passes and roll-call; other occupants and internal history are removed from family payloads. Accountant receives no boarding records or write controls.

Rooms record capacity, Available/Unavailable state, optional configured gender policy, warden/contact, archive and dated review history. Student/room transactions prevent concurrent cross-room allocation and over-capacity admissions. Only active students can be allocated; archived/unavailable rooms reject intake. Bed labels are recorded explicitly, not inferred for historical occupants. Versioned reviews cannot reduce capacity below boarders or impose a conflicting gender policy. Discharge retains a reason/history and is blocked by active gate passes. Empty rooms may be archived/restored.

Staff or an authorized family requests a dated gate pass for an allocated active boarder. Overlapping active requests serialize per student. Families can cancel only a pending own-family request; approval and physical gate transitions remain staff actions. Approval requires pickup name/phone and explicitly recorded guardian consent. Departure is allowed only within approved dates and records an actual timestamp; return requires an actual Out state and records its timestamp. Rejection/cancellation/return remain saved. Consent is a staff verification record, not an external digital-consent integration.

Roll-call shows current boarders explicitly Unmarked until a confirmation is saved. Corrections require version/reason; future marks are rejected and Teacher backdating requires office review. On leave requires an actually departed gate pass. Bulk present confirmation preserves all existing marks and excludes departed boarders; it records only unmarked confirmations and does not alter existing correction versions. Date switching refreshes the correct register. Historical occupancy snapshots, separate morning/evening sessions and holidays remain future work.

Maintenance stores actual work status, repair/next action, versioned reasons and resolution history. Resolving/reopening never silently deletes the request. Room inspections, custody identity verification, external emergency delivery, automated dormitory billing and atomic cross-room transfers remain separate capabilities; current moves use reviewed discharge/allocation.
